## How to a/b test LinkedIn outreach inside HeyReach (and actually trust the results)
- **source_type:** blog_post
- **source_url:** https://www.heyreach.io/blog/how-to-a-b-test-linkedin-outreach
- **topics:** analytics-benchmarks, sequences-campaigns, copywriting-messaging, heyreach-product, linkedin-outreach, sales-process
- **strategies/playbooks:** Run VALID LinkedIn A/B tests. Core problem: running two separate campaigns with the same sender is NOT a valid test — sender capacity distributes proportionally across active campaigns with priority to whichever launched first, so the later campaign gets the remainder ("Campaign A didn't win because of the copy. It won because it launched first"). Three conditions of a valid test: (1) Equal exposure (comparable, roughly equal send volume per version), (2) Isolation (change only ONE variable — copy OR CTA OR note, not all), (3) Consistency (no edits/ICP changes/sender swaps from launch to read). Clean-test steps: Step 1 — use native "Add Message Variation" inside ONE campaign (in the Send Connection Request panel; also available in Send Message and InMail steps); 2 versions recommended (more variations = fewer leads/version, noisier). Step 2 — change exactly one variable (e.g., opener angle: role-specific hook vs problem statement), keep sender/list/CTA identical. Step 3 — set threshold before launch (~100 leads per version as a practical baseline, not a statistical rule). Step 4 — lock the campaign (no edits, ICP changes, sender swaps, list additions). Step 5 — at threshold, compare acceptance rate & reply rate; >a few percentage points = directional signal; small gap = variable doesn't move the needle; log either way. Variable test order: connection note copy first (entry gate, resolves in one cycle via acceptance rate) → then follow-up opener → CTA/timing last.
- **frameworks/methods/tools:** "Add Message Variation" (HeyReach native A/B). Metrics framework: Acceptance rate (is the connection request landing — friction at entry?), Reply rate (does interest turn into conversation — follow-up issue?), Reply-to-acceptance rate (where the drop happens; proxy for conversion). Four-column test-log Google Sheet: Version / Sender+volume / Result (acceptance & reply w/ raw numbers) / Decision. Dashboard CSV export to populate the log or CRM.
- **product/features:** Add Message Variation in Connection Request / Send Message / InMail steps; per-sender sending limits (root cause of uneven distribution); dashboard CSV export; campaign performance comparison per version.
- **opinions/hot-takes:** "Most teams don't need more tests. They need valid ones." "If your tests aren't valid, your system isn't learning." Checking early = same as a mid-campaign edit ("you can't un-split a data pool").
- **numbers/benchmarks:** KEY BENCHMARK — across 96,051 HeyReach campaigns, median acceptance ~21% and reply rate ~22% (measured against campaigns targeting qualified leads, NOT cold spray lists). Threshold guidance ~100 leads per version. Warns a "12% reply rate on day two" may really be just twelve replies.

- **voice/quotes:** "You have data. You don't have a test (yet)."; "That's the difference between an outreach system that compounds and one that just runs."
