## AI outreach agent: From sequences to systems that think

- **topics:** ai-outreach, ai-sdr-agents, heyreach-product, automation-stack, multichannel, personalization, deliverability-safety-bans, integrations
- **strategies/playbooks:**
  - Core thesis: move from rule-based "sequences" to autonomous "AI outreach agents" that research, personalize, execute, and learn. Rule-based tool = "send Message B if no reply after 3 days"; AI agent observes that for a persona/season waiting 5 days gets higher replies and adjusts dynamically.
  - 4 agent functions: (1) Prospecting — pull leads from enrichment (Clay, databases), filter by ICP (titles, company size, geography), dedupe; via MCP, Claude instructs HeyReach to clean list before sending (remove interns, mis-titles, stale leads). (4) Learning — updates probabilities from positive/negative/no-reply, shifts timing/channel mix.
  - Deploy in 4 steps: **Step 1 (ICP + data):** define precise ICP attributes (title, seniority, company size, location, tech stack) as structured fields; pull Clay enrichment; clean dataset (remove invalid LinkedIn URLs, dup domains, bounced emails) using HeyReach import validation; feed validated data via MCP endpoint. **Step 2 (train agent):** export historical HeyReach data (templates, reply tags, timestamps), transform into training schema JSON {message, reply_type, time_to_reply, channel}, store in MCP memory or Claude system prompt, load active campaigns, initialize in **sandbox mode** (generates but doesn't execute; messages visible in Unibox for manual approval). **Step 3 (autonomy levels):** set execution flags in MCP config permissions {send_messages:false, auto_followups:true, tag_replies:true}; deploy n8n conditional triggers (reply_tag positive→pause campaign; neutral→queue follow-up; bounce→remove lead+log error); escalate autonomy Phase 1 drafts only → Phase 2 follow-ups → Phase 3 full execution within guardrails. **Step 4 (measure beyond vanity):** collect structured reply data via MCP {reply_id, sentiment, intent, timestamp}; track operational metrics (delivery success, avg response delay, follow-up completion, campaigns paused on positive replies) + business metrics (positive replies→SQL, SQL→meetings, meetings→closed-won); feed performance back to Claude, update prompt with structured learnings, regenerate templates.
- **frameworks/methods/tools:** 6-layer agentic architecture — (1) Input layer (ICP dataset from CSV/CRM/Clay + campaign metadata), (2) Reasoning layer = Claude (decides next best action), (3) Bridge layer = MCP (converts reasoning into machine-readable commands: send/pause/tag/update), (4) Execution layer = HeyReach (validates vs LinkedIn limits/proxy/account status, executes, logs), (5) Orchestration layer = n8n (pauses campaigns, syncs CRM, Slack alerts), (6) Feedback loop. Tools: HeyReach MCP, Claude/Anthropic, Clay (enrichment, job changes/company info), n8n, Slack, Webshare (rotating proxies).

## Automate your LinkedIn outreach campaign reports
- **source_type:** blog_post
- **source_url:** https://www.heyreach.io/blog/campaign-reports
- **topics:** client-reporting, automation-stack, heyreach-product, integrations, agency-operations, analytics-benchmarks
- **strategies/playbooks:** Two n8n workflows to automate weekly LinkedIn outreach reporting using HeyReach's native n8n nodes:
  - **Version 1 (weekly performance summary):** (1) Schedule/cron trigger fires every Monday 00:00 ("You always start the week with the previous week fully closed"). (2) Pull total/lifetime campaign stats via HeyReach node "Get overall stats" (total invites sent, overall acceptance rate, cumulative replies, total messages, channel metrics) — no HTTP requests/JSON needed. (3) Define time window: end date = now, start date = 7 days ago (store as variables; n8n date library subtracts days). (4) Pull last 7 days stats (invites, accepted connections, sent messages, replies, reply rate, per-campaign interactions). (5) Generate Gmail draft (subject from reporting date, insert weekly+total stats into prewritten template, add client emails to CC/To). Formatting trick: split ISO timestamp by "T" to drop the time portion for a clean subject line. (6) Append weekly stats as a new row in a dedicated Google Sheet (start/end dates, weekly metrics, optional lifetime) → master file for trend tracking/forecasting.
  - **Version 2 (summary + replied leads):** adds a fresh spreadsheet tab per week of leads who replied. Steps: prepare variables (spreadsheet ID, main sheet name, new weekly sheet name, date formats with/without timestamps); create new sheet (e.g. "Leads — 2025-11-13"); add header columns via IF/Else only if sheet is new (first name, last name, job title, company, LinkedIn profile, email, message status, timestamp); re-retrieve stats (branch merge); fetch all campaigns (3/10/40); split campaigns and fetch leads campaign-by-campaign (profile metadata, message history, messageStatus, timestamps); filter leads where **messageStatus == "MESSAGE_REPLY"** (replied within period); add replied leads to weekly sheet; format human-readable list via code node (e.g. "- Jane Smith (Head of Growth, OrbitLabs) / LinkedIn: ... / Email: jane@orbitlabs.io"); generate enhanced Gmail draft (weekly + total stats + formatted replied-leads list). "The workflow does 95% of the reporting work." "Most agencies end up using Version 2."
  - Common mistakes: (1) forgetting to enable "Always output data" when creating weekly sheet (if sheet exists n8n returns empty, workflow stops); (2) using dynamic sheet names directly in nodes (generate name once, store in variable); (3) API rate-limit "too many requests" when looping many campaigns in same second → enable retry-on-fail with short delay (e.g. 2 seconds); (4) missing Gmail fields from wrong branch/item index; (5) empty weekly reply tab is expected (not an error) when no one replied.

## Automated data enrichment: Fueling high-scale LinkedIn outreach
- **source_type:** blog_post

- **strategies/playbooks:** Core thesis: outreach failure is usually a DATA problem, not a messaging problem; shift from "list → sequence → hope" to "data → signals → automated outreach → real conversations," and from ICP-fit ("who fits our ICP?") to **signal-based targeting** ("who actually needs this now?").
  - **Data waterfall** (sequence multiple providers/steps because no single provider has full coverage): (1) **Source** — raw lead input (LinkedIn profile, Sales Navigator export, or trigger-based lead like new hire/funding). (2) **Validate** — clean/verify basics (valid LinkedIn URL? company exists? key fields present?) to avoid wasting credits. (3) **Enrich** — layer sources: one provider firmographics (company size, industry, revenue), another tech stack, another hiring/growth signals. (4) **Qualify** — filter on signals (only keep companies hiring SDRs / using a specific tool / with a key signal). (5) **Route** — push qualified lead directly into HeyReach campaign (no manual export).
  - Build enrichment engine in **Clay** as the control layer / "GTM command center": start with a table (Sales Nav profiles, trigger-captured leads, existing data); each column = a waterfall step (company data, tech stack, hiring signals, AI summaries); connect 50+ data sources in one workflow; add conditional logic (only enrich if matches ICP / key fields missing / signal detected — e.g. "hiring SDRs → continue; if not → stop") to save credits and keep pipeline high-intent; **run expensive steps last** (email finding, phone numbers, AI summaries only after a lead is qualified); enable **auto-update** for always-on real-time enrichment.
  - Connect Clay → HeyReach: in Clay table add column "HeyReach → Add Lead to Campaign" → Manage accounts → Add connection → in HeyReach go Integrations → API → generate API key → paste into Clay. Prep HeyReach campaign first (create campaign, define lead list, select LinkedIn senders, build sequence). Use dynamic variables pulling from enriched data: {firstName}, {companyName}, {websiteSummary}, {AI_Icebreaker_1} — field names must match between Clay and HeyReach. Map standard + custom fields; with Clay auto-update, new qualified leads sync continuously.
  - **Trigger-based outreach** examples (signals): company hired SDRs, raised funding, adopted a new tool, new Head of Sales joined. Message example — instead of "Hey John, saw you're in sales at X company…" send "Hey John, noticed you're hiring SDRs right now, are you scaling outbound internally or exploring tools to support that?"
  - **"Invisible touch" end-to-end workflow:** Step 1 capture lead/trigger → Step 2 enrich via waterfall in Clay → Step 3 qualify on signals → Step 4 push to HeyReach automatically via API (map standard + custom fields; continuous if auto-update on) → Step 5 launch personalized outreach at scale (multiple senders, sequence, dynamic variables) → Step 6 manage conversations in Unified Inbox.
  - Common mistakes: treating enrichment as one-time (data decays immediately); enriching entire lists upfront (wasteful — enrich in stages, qualify early, expensive steps last); skipping the qualification layer ("Enrichment without qualification is just more data – not better targeting"); not syncing enrichment with outreach (manual CSV export breaks the system); overcomplicating the stack; focusing on volume over precision.
  - Role operationalization: SDRs shift from manual research → responding in Unified Inbox/building conversations (leads arrive pre-enriched, pre-qualified, already in campaign); agencies build repeatable playbooks (standard enrichment waterfall for SaaS clients, predefined signal-based campaigns, reusable Clay workflows) — plug in new client ICP, adjust signals, launch; GTM engineers own the infrastructure (build/maintain Clay workflows, define qualification logic, connect APIs Clay → HeyReach → CRM).

## Autonomous AI agents in B2B sales: What works and what quietly breaks
- **source_type:** blog_post
- **source_url:** https://www.heyreach.io/blog/autonomous-ai-agents
- **topics:** ai-sdr-agents, ai-outreach, deliverability-safety-bans, automation-stack, targeting-icp-lists, heyreach-product, analytics-benchmarks, sales-process
- **strategies/playbooks:** How to build a production autonomous outbound stack (Clay + n8n/Make + HeyReach) that survives real (bad) data:
  - **3 decisions before building:** (1) Write a specific handoff document listing where the agent decides vs. where humans do (e.g. "agent personalizes the opener based on signal type, but a human approves before the first message goes to a Tier 1 account"; "any reply with a question routes to a human within 4 hours") — "If the team can't produce this document, the agent doesn't have guardrails — it has vibes." - **strategies/playbooks:** Three real HeyReach-user agency campaigns with verbatim message templates + results + replication steps.
  - **Campaign 1 — Bridger (recruiting Product Managers, EN/Germany market):** Prospect list sourced from a third-party recruiter CRM, imported to HeyReach via CSV, targeting people marked "open to work." **Connection request: blank (no message).** Follow-up 1 thanks for accepting + shares a Notion job-description link + asks them to share "boundary conditions" and book a call. Follow-up 2 = short check-in. Follow-up 3 = polite break-up ("Apparently, my timing is not right right now"). Sequence actions used: LinkedIn invites, profile views, post likes, messages. Replication: target "open to new opportunities" users; be direct; personalize with name + specifics; keep conversation focused on fit; space out follow-ups; use HeyReach to import + automate.
  - **Campaign 2 — Ghostify (mindset coaching for UK-based Directors):** List-building via LinkedIn **"Posted on LinkedIn" filter** (target active users) for warm intros; offer = free 1:1 discovery call. **Connection request: blank (no message).** Follow-up 1 = long value-led pitch (question hook "what would it mean to you to achieve Mindset Mastery?" + benefits + free Discovery Call invite + "P.S. Our clients are often SHOCKED..."). Follow-ups 2-4 = escalating nudges ending with a break-up ("I'll leave the ball in your court!"). Replication: narrow audience via Advanced Filters; clear value prop / free consult upfront; use templates but tailor with thought-provoking questions; plan a follow-up sequence; use HeyReach multiple senders w/ auto-rotation + respond on behalf of others without logging in/out, using tags/filters/reminders; monitor + refine.
